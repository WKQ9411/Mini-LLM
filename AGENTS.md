# Project Notes

- The project requires Python 3.12 (`>=3.12,<3.13`), matching the Python version installed by the interactive setup scripts.
- The project targets `transformers==5.13.0`.
- Custom model configs use the Transformers 5.x declarative `@strict` style: define typed class fields, keep only derived values in `__post_init__`, and delegate unknown legacy fields to `PreTrainedConfig.__post_init__`.
- Define RoPE through `rope_parameters`. Transformers 5.x migrates checkpoint-era `rope_theta` and `rope_scaling` fields during config loading; model code should only consume the normalized dictionary.
- Custom model configs should explicitly set `tie_word_embeddings=True` when input embeddings and `lm_head` are shared, so old checkpoints saved without `lm_head.weight` can be loaded through the tied-weight mapping.
- Custom model configs should explicitly define `pad_token_id`, `bos_token_id`, and `eos_token_id`, matching Transformers 5.x language-model config conventions.
- Legacy generation-only config fields should not be preserved on model configs; Transformers 5.x expects them in `generation_config.json`.
- Model `_tied_weights_keys` should use the Transformers 5.x mapping form: `{"target.weight": "source.weight"}`.
- `transformers.masking_utils.create_causal_mask` and `create_sliding_window_causal_mask` in 5.x do not accept `cache_position`; pass `past_key_values` and `position_ids` instead.
- Model attention paths use the explicit PyTorch attention implementations. The standalone Triton Flash Attention module is benchmark-only and is not wired into configs, model prefill, or example CLIs.
- Models that require project-specific cache objects should override `_supports_default_dynamic_cache()` to return `False`, so `generate()` lets model code initialize the custom cache.
- `RotaryEmbedding.inv_freq` is a non-persistent buffer. Rebuild it on the first forward pass instead of relying on Transformers 5.x `from_pretrained()` to retain its constructor value.
- `mini_inference` has an independent MiniLlama3 inference model that loads the training checkpoint directly into packed projections and uses the block KV cache attention path; it does not use Transformers generation or cache classes.
- MiniLlama3 under `mini_inference` is single-GPU only. Keep its projection sizes and KV cache head counts unsharded, and reject `tensor_parallel_size` values other than 1.
- `mini_inference.Config.dtype` is the inference compute dtype and must resolve to `torch.float16` or `torch.bfloat16`. MiniLlama3 defaults to bfloat16 when it is omitted, and checkpoint tensors are converted while loading because the Flash Attention kernels do not accept float32 inputs.
- Keep MiniLlama3 RoPE inside each inference attention layer and share its precomputed cache through the nano-vLLM-style `get_rope()` factory. Default RoPE and YaRN are supported; YaRN must reuse `mini_models.rope.compute_yarn_parameters()` so training and inference use the same interpolation and attention-scaling calculation.
- `mini_inference.SamplingParams` mirrors the sampling controls in `mini_models.Generator`: temperature, top-k, top-p, repetition penalty, and frequency penalty. Apply penalties only to generated tokens and preserve the order penalties, temperature, top-k, top-p, then greedy or exponential-noise sampling.
- Keep custom inference kernels under `mini_inference/kernels`. `mini_inference.Config.attention_backend` selects either the project Triton kernels or the third-party `flash-attn` functions when the model is initialized; keep the selected backend fixed for the model lifetime and import only that backend.
- The custom Flash Attention kernels are compact inference-forward learning implementations and expose only parameters used by `Attention`. Varlen prefill supports contiguous or paged KV, while decode reads paged KV; both support FP16/BF16, GQA/MQA, and causal masking.
- `eval/eval_inference_throughput.ipynb` is the unified MiniLlama3 inference benchmark. It compares Batch 1 prefill backends, attributes Batch 1 decode gains to CUDA Graph, compares Triton and flash-attn end to end under CUDA Graph, and measures Triton CUDA Graph Continuous Batching across concurrency levels.
- `scripts/setup.ps1` and `scripts/setup.sh` are the interactive setup entry points. They keep main environment, Architecture Lab frontend, and flash-attn installation separate; flash-attn prefers an exact official wheel and requires confirmation before a source build. The PowerShell entry point targets both Windows PowerShell 5.1 and PowerShell 7, and must remain UTF-8 with BOM. Both entry points delegate Python runtime inspection to `scripts/setup_helper.py`; do not pass embedded Python source through shell arguments or pipelines. System and component status are detected at startup and cached when returning to the menu; refresh the component cache silently after a successful installation.
